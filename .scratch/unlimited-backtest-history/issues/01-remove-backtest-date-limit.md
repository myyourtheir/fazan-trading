# 01: Запускать все бэктесты без лимита дат

**Что сделать:** Владелец может запустить «Сёрфинг» или «Улучшенный сёрфинг» за период длиннее 30 дней, если пригодной истории и предыстории достаточно. Старый API без `kind` поддерживает такие же длинные запросы. Все варианты рассчитывают EMA по завершённым свечам без обращения за брокерской EMA.

**Блокеры:** нет, можно начинать сразу.

Status: done

- [x] Проверка истории и запуск принимают корректный диапазон длиннее 30 календарных дней во всех трёх вариантах. Вместо снятого лимита нет нового общего потолка по дням или свечам.
- [x] Свечи загружаются порциями в пределах ограничений брокера для каждого таймфрейма и объединяются по времени открытия без дублей. Границы порций не меняют значения EMA.
- [x] Все прогоны используют локальную EMA с начальным средним по закрытиям и коэффициентом `2 / (N + 1)`. Источник EMA указан в отчёте. ATR и источник живой EMA не меняются.
- [x] В форме не показывается 30-дневный лимит. Сохраняются ограничения периодов индикаторов, проверка порядка дат и действующие правила часовых поясов и незавершённого дня.
- [x] Публичные REST-тесты с подменным источником покрывают успешный длинный запрос во всех вариантах, стыки порций и локальную EMA без вызовов брокерского индикатора.
