# 02: Считать по доступным границам и объяснять отсутствие результата

**Что сделать:** Если свечи выбранного контракта есть только за часть запрошенных дат, владелец получает результат по доступной истории. Он видит запрошенный и фактический диапазоны рядом с результатом, а в форме остаются выбранные даты. Если загрузка не дала пригодной истории, приложение объясняет причину и не заменяет предыдущий отчёт.

**Блокеры:** 01 — запускать все бэктесты без лимита дат.

Status: done

- [x] Все варианты проверки истории и запуска используют пригодную часть диапазона, даже если запрос начинается до начала торгов контрактом или заканчивается после них. Другой контракт не подставляется.
- [x] Фактический диапазон ограничен первой и последней пригодными свечами внутри запроса. При неполных границах рядом с отчётом постоянно видны оба диапазона и сообщение «На границе диапазона нет свечей». Отсутствие свечей на выходном не выдаётся за доказанную потерю данных.
- [x] Успешный пустой ответ («За выбранный период нет свечей»), наличие только непригодных свечей и сбой загрузки («Не удалось загрузить свечи») различимы. Сбой необходимой порции не трактуется как отсутствие свечей; новый торговый результат в этих случаях не появляется.
- [x] Неудачная попытка сохраняет предыдущий успешный отчёт и не выдаёт его за результат нового запроса. Предупреждение в отчёте относится к его параметрам и не меняет даты в форме.
- [x] Публичные REST-тесты покрывают неполные границы, выход за срок торгов контрактом, отсутствие данных и сбой загрузки. Браузерный тест проверяет длинный запрос, частичный отчёт, неизменные даты в форме и сохранение отчёта после неудачного повторного запуска.
