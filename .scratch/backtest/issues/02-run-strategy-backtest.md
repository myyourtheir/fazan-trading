# 02: Получить первый отчёт по стратегии

Status: ready-for-agent

**Что сделать:** Дать владельцу запустить бэктест «Сёрфинга» на проверенных исторических данных и получить отчёт без комиссии и проскальзывания. Отчёт показывает, когда и почему менялась позиция и каким оказался денежный результат, не затрагивая торговлю.

**Блокируется:** [01 — Проверить исторические данные на `/backtest`](01-validate-historical-data.md).

**Спецификация:** [Бэктест стратегии «Сёрфинг»](../spec.md).

## Критерии приёмки

- [ ] «Запустить бэктест» возвращает отчёт для выбранных параметров или понятную ошибку. Полные данные без пересечений дают обычный отчёт с нулём исполнений.
- [ ] Прогон начинается из нуля; история до периода только задаёт исходную сторону. Вход в обе стороны возможен лишь по подтверждённому пересечению. Касание EMA не сбрасывает прежнюю строгую сторону и не вызывает исполнения.
- [ ] Исполнение моделируется на открытии следующей завершённой свечи внутри периода, в том числе после паузы между сессиями. Вход занимает `N` лотов, переворот отображается одной строкой на `2N`. Сигнал без следующей свечи показан отдельно и не меняет позицию или счётчик исполнений.
- [ ] Отчёт показывает денежный итог, результат закрытых сделок и открытой позиции, остаток позиции, число исполнений и снимок параметров. Остаток оценивается по закрытию последней свечи без искусственного закрытия.
- [ ] Отчёт указывает валюту, коэффициент пересчёта по шагу цены и стоимости шага фьючерса и допущение об использовании параметров контракта на момент прогона. При их отсутствии денежный отчёт не выдаётся.
- [ ] На графике есть отметки в моменты исполнений; таблица показывает время по Москве, направление, лоты и цену. Отчёт явно говорит, что комиссия и проскальзывание не учитываются.
- [ ] Прогон не отправляет заявки, не подписывается на живой поток и не меняет состояние робота, счёт или торговый журнал. REST-тесты с подменным брокером покрывают эти гарантии, расчёт и пограничные сценарии.
