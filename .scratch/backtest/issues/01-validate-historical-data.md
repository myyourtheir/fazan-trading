# 01: Проверить исторические данные на `/backtest`

Status: done

**Что сделать:** Дать владельцу защищённую страницу, на которой он может выбрать контракт и период и проверить, пригодны ли свечи и EMA Т‑Инвестиций для прогона. До появления расчёта интерфейс явно называет результат проверкой данных, а не отчётом о сделках.

**Блокируется:** ничем.

**Спецификация:** [Бэктест стратегии «Сёрфинг»](../spec.md).

## Критерии приёмки

- [x] На `/backtest` можно явно выбрать один фьючерс и задать таймфрейм, период EMA, размер позиции в лотах и диапазон дат. Обе даты включительны по Москве, часовой пояс указан. Запрос выполняется только по явному действию.
- [x] Проверка работает через защищённый REST без выбранного счёта и не зависит от робота, позиции или сохранения настроек. Сервер проверяет параметры, порядок дат и лимит; форма показывает тот же лимит.
- [x] При успехе график показывает завершённые свечи и брокерскую EMA по совпадающему времени открытия. История до периода позволяет найти последнюю строгую сторону; порции диапазона не создают дубликаты.
- [x] При отсутствии необходимых свечей, EMA или исходной строгой стороны интерфейс показывает причину вместо частичного результата. Перерывы между торговыми сессиями сами по себе не ошибки; локальная EMA не подменяет брокерскую.
- [x] Отдельная проверка с разрешённым токеном песочницы обосновывает заявленный лимит и фиксирует поддерживаемые комбинации параметров, покрытие и согласованность EMA на стыках. Эта проверка также подтверждает доступность параметров контракта, необходимых для денежного пересчёта в 02. Без проверки не заявлять покрытие как подтверждённое.
- [x] Автоматические тесты через публичный REST с подменным брокером проверяют авторизацию, валидацию, московские границы, сопоставление данных и ошибки неполного покрытия без реального токена.

## Comments

Сделан предварительный экран и REST-проверка согласованности. Семь календарных дней — предел запроса, а не подтверждённое покрытие песочницы. [Инструкция проверки песочницы](../../../README.md#проверка-исторических-данных).

При проверке нужно подтвердить реальное покрытие и определить, как отличать одновременное отсутствие свечи и EMA от паузы между сессиями: сопоставление двух рядов само по себе этого не доказывает. Пока эти вопросы открыты, задачу не закрывать и не считать блокировку 02 снятой.

Проверка песочницы выполнена (токен владельца, `IMOEXF` UID `5bcff194-f10d-4314-b9ee-56b7fdb344fd`, период 2026-11-05–2026-11-11). Подтверждено: полные свечи и брокерская EMA за семь дней для 5m/15m/30m/1h и EMA 5/55/1000; параметры контракта доступны (валюта `rub`, лот `1`, шаг цены `0.5`, стоимость шага `5` — коэффициент для денежного пересчёта в 02). Паузы между сессиями (выходные, закрытие сессии) корректно не считаются пропусками.

При проверке вскрылись две проблемы стыков порций, обе исправлены: (1) EMA на стыке двух запросов `GetTechAnalysis` пересчитывается от своего начала и отличается на последний бит, из-за чего строгое сравнение `Object.is` давало ложный `BACKTEST_HISTORY_CONFLICT` — заменили на допуск относительной погрешности; (2) стык порций при 5-минутках всегда попадает на закрытие сессии (23:50 МСК), поэтому наложения нет — проверка теперь не требует его для 5m, а только фиксирует, что согласованность реально проверена хотя бы на одном торговом дне.
