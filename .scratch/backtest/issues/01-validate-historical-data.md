# 01: Проверить исторические данные на `/backtest`

Status: ready-for-agent

**Что сделать:** Дать владельцу защищённую страницу, на которой он может выбрать контракт и период и проверить, пригодны ли свечи и EMA Т‑Инвестиций для прогона. До появления расчёта интерфейс явно называет результат проверкой данных, а не отчётом о сделках.

**Блокируется:** ничем.

**Спецификация:** [Бэктест стратегии «Сёрфинг»](../spec.md).

## Критерии приёмки

- [ ] На `/backtest` можно явно выбрать один фьючерс и задать таймфрейм, период EMA, размер позиции в лотах и диапазон дат. Обе даты включительны по Москве, часовой пояс указан. Запрос выполняется только по явному действию.
- [ ] Проверка работает через защищённый REST без выбранного счёта и не зависит от робота, позиции или сохранения настроек. Сервер проверяет параметры, порядок дат и лимит; форма показывает тот же лимит.
- [ ] При успехе график показывает завершённые свечи и брокерскую EMA по совпадающему времени открытия. История до периода позволяет найти последнюю строгую сторону; порции диапазона не создают дубликаты.
- [ ] При отсутствии необходимых свечей, EMA или исходной строгой стороны интерфейс показывает причину вместо частичного результата. Перерывы между торговыми сессиями сами по себе не ошибки; локальная EMA не подменяет брокерскую.
- [ ] Отдельная проверка с разрешённым токеном песочницы обосновывает заявленный лимит и фиксирует поддерживаемые комбинации параметров, покрытие и согласованность EMA на стыках. Эта проверка также подтверждает доступность параметров контракта, необходимых для денежного пересчёта в 02. Без проверки не заявлять покрытие как подтверждённое.
- [ ] Автоматические тесты через публичный REST с подменным брокером проверяют авторизацию, валидацию, московские границы, сопоставление данных и ошибки неполного покрытия без реального токена.
