# Пул агентов OpenCode

Проектный `orchestrator` — основной агент. Он владеет разговором с пользователем, передаёт работу по ролям и принимает результат. `architect` проектирует и пишет подробные спецификации и локальные тикеты; `implementer` пишет код и тесты; `reviewer` независимо проверяет изменения.

Architect обязателен при создании тикетов через `@grill-with-docs` и при проектировании новых возможностей, контрактов, схемы БД или торгового поведения. Небольшое исправление с готовыми критериями идёт сразу к Implementer, затем к Reviewer. При наличии тикета переиспользуется существующий, если не запрошено новое разбиение.

При `@grill-with-docs` Architect работает в одной дочерней сессии. Он отдаёт раунды вопросов и запросы на исследование Orchestrator; тот передаёт вопросы пользователю и возвращает ответы и факты в ту же сессию. Публикация документов и тикетов требует явного подтверждения; реализация требует отдельного запроса. Так workflow не зависит от форм вопросов в фоновых сессиях и не требует увеличения глубины сабагентов.

| Роль | Основная модель | Согласованный резерв |
| --- | --- | --- |
| Orchestrator | `openai/gpt-6-luna#low` | `ollama-cloud/minimax-m3.1-flash#low` |
| Architect | `openai/gpt-6.2-sol#high` | `ollama-cloud/deepseek-v4-pro:0813#high` |
| Implementer | `openai/gpt-6.1-terra#medium` | `ollama-cloud/minimax-m3.1-flash#medium` |
| Reviewer | `openai/gpt-6.2-sol#medium` | `ollama-cloud/deepseek-v4-pro:0813#high` |

Экономия: недорогая координация, отдельный архитектурный проход только по необходимости, компактные передачи контекста, без параллельных дублирующих проходов по умолчанию. Не обещаем конкретную стоимость без тарифных данных OpenAI.

Переключение на Ollama Cloud — только при подтверждённом исчерпании квоты/бюджета, не при временном rate limit, сетевой ошибке или ошибке авторизации. Автоматика использует уже подключённые интеграции OpenCode, без нового платного аккаунта, внешнего прокси и копирования токенов. OpenCode V2 не предоставляет штатного перехода при ошибке квоты; используем локальные штатные API и хуки для будущих ходов, а не для миграции текущего запроса.

После подтверждённой ошибки будущие ходы управляемых ролей переключаются на Ollama Cloud; текущий запрос не повторяется, а его состояние сохраняется. Пользователь получает статус и явно указывает, когда продолжить. Режим резервного провайдера действует только для этого проекта и сохраняется при перезапуске до ручного возврата на OpenAI. Не делаем проверочных запросов на OpenAI, не выбираем третий провайдер. Если покрытие публичными API или сигнатура OAuth-ошибки не подтверждаются, сообщаем, что именно не поддержано, и не заявляем готовый автопереход.
