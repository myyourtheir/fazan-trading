## Acceptance criteria

- Новый сеанс в проекте по умолчанию использует ID `orchestrator` и GPT-6 Luna с low reasoning (учесть, что root `model` не сохраняет `#variant`, использовать документированную настройку модели при необходимости). Три другие роли — сабагенты с model refs из спецификации.
- `@grill-with-docs` при создании тикетов направляется Architect; child получает исходную задачу и команду загрузить skill. Orchestrator передаёт раунды вопросов и результаты нужного факт-файдинга в ту же сессию без вложенного запуска сабагентов. Создание документов после подтверждения, и не запускается реализация без отдельного запроса. Другие триггеры Architect и обход архитектурного прохода — по спецификации.
- Orchestrator передаёт код и тесты Implementer, проверку — Reviewer, управляет исправлениями и повторной проверкой; не выдаёт незавершённый review за одобрение. Reviewer остаётся без прав записи и shell. Сохранить полезные существующие проектные инструкции и не трогать несвязанные настройки.
- В короткой проектной документации описаны роли, триггер, проверка в новом сеансе, оговорка об уже выбранной модели в существующих сеансах и отсутствие настроенного failover. Согласованное сопоставление резервных моделей не должно выглядеть как активная конфигурация.
