# 09: Восстановление потока и перезапуск сервера

Status: ready-for-agent

**Что сделать:** Автоматически восстановить поток после обрыва и безопасно восстановить состояние после перезапуска, не отправляя заявки по пропущенным свечам.

**Блокируется:** [08 — Сверка проблемной заявки и ручное возобновление](08-order-reconciliation-and-resume.md).

## Критерии приёмки

- [ ] При обрыве потока брокера панель показывает его состояние. После повторного подключения бэкенд догружает пропущенные свечи и EMA, объединяет обновления без дубликатов и восстанавливает исходную сторону EMA.
- [ ] Если разорван только WebSocket браузера, робот продолжает работу на бэкенде. Фронтенд переподключается, перечитывает актуальные данные через REST и объединяет их с живыми обновлениями без дубликатов.
- [ ] История, догруженная после разрыва, обновляет график, но не выставляет заявки. Новый подтверждённый сигнал после восстановления может быть обработан, если робот ранее был запущен и не заблокирован сверкой.
- [ ] После перезапуска доступны настройки и журнал, фактическая позиция и нерешённые заявки сверяются с брокером. Без ручного запуска новые заявки не отправляются.
- [ ] Повтор уже обработанной свечи после перезапуска не создаёт новую заявку. Заявка с неясным статусом сверяется только по сохранённому ID.
- [ ] Тесты с подменным брокером покрывают обрыв с пропущенным пересечением и пересечение после восстановления. Проверка с PostgreSQL подтверждает сохранение настроек, журнала и защиты от повторной отправки при перезапуске.
