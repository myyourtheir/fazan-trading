# 08: Сверка проблемной заявки и ручное возобновление

Status: done

**Что сделать:** Позволить владельцу выяснить судьбу проблемной заявки и вручную возобновить торговлю только после сверки с брокером.

**Блокируется:** [05 — Первый вход и журнал исполнений](05-first-entry-and-execution-history.md).

## Критерии приёмки

- [x] Отказ, частичное исполнение, тайм-аут или расхождение позиции ставят робота на паузу. В панели видны причина, сведения о заявке и фактическая позиция либо явная отметка, что позицию не удалось подтвердить.
- [x] Сверка использует сохранённый исходный клиентский ID заявки. Тайм-аут сам по себе не считается доказательством, что брокер не получил заявку. Автоматической повторной отправки нет.
- [x] Журнал обновляется после сверки с учётом статусов и фактических исполнений. При неясном статусе, активной заявке или несверенной позиции возобновление заблокировано.
- [x] После сверки торговля возобновляется только по команде владельца.
- [x] Тесты покрывают отказ, частичное исполнение, тайм-аут с последующим обнаружением заявки и всё ещё неизвестный результат. Они подтверждают, что повторного вызова на отправку не было.
