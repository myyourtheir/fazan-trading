# 04: Подключить «Сёрфинг» к live и backtest через контракт

**Что сделать:** Завершить переход текущих сценариев на декларативное определение «Сёрфинга», сохраняя отдельные live- и backtest-исполнение и позволяя в будущем добавить стратегию собственными параметрами и адаптерами.

**Блокируется:** [02 — Ввести декларативный контракт стратегии](02-declare-strategy-contract.md), [03 — Перенести настройки на тип стратегии](03-migrate-settings-to-strategy-kind.md).

**Статус:** done

- [x] «Сёрфинг» — единственная зарегистрированная production-стратегия и явно связан с live- и backtest-адаптерами в композиции приложения.
- [x] Live использует брокерскую EMA для той же завершённой свечи и сохраняет резервирование до отправки, проверку позиции, обработку неопределённых результатов и исходный ID заявки.
- [x] Backtest использует параметры своего запроса и локальную EMA; он сохраняет исполнение на следующем доступном открытии, конечный сигнал без исполнения и текущий денежный отчёт.
- [x] Прогон не меняет состояние робота, счёта или торгового журнала.
- [x] REST/API и существующий интерфейс продолжают работать без выбора второй стратегии; текущие запросы и журнал совместимы.
- [x] Проходят тесты core, сценариев Robot, backtest, REST и миграции, а также проверка слоёв backend, lint и format check затронутых приложений.
