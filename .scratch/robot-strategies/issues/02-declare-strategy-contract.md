# 02: Ввести декларативный контракт стратегии

**Что сделать:** Позволить разработчику подключить стратегию с её собственными параметрами и валидацией, чистым правилом решения, а также явными live- и backtest-подключениями, не добавляя вторую production-стратегию.

**Блокируется:** [01 — Выделить проверяемое решение «Сёрфинга»](01-extract-surfing-decision.md).

**Статус:** done

- [x] Определение стратегии имеет стабильный `kind`, типизированные параметры, валидацию, правило решения и явные адаптеры live/backtest.
- [x] Параметры остаются специфичными для стратегии; контракт не требует EMA или фиктивных общих настроек.
- [x] Пример тестового определения с другой формой параметров подключается без изменений правил оркестрации, но не появляется в production-каталоге.
- [x] Решение возвращает отсутствие сигнала либо целевую позицию с типизированным объяснением; позиция и состояние ордера не включаются в состояние правила.
- [x] Выбор и композиция явны, без DSL, автопоиска плагинов и универсального движка исполнения.
