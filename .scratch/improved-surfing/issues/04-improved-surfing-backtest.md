# 04: Добавить полный бэктест стратегий

**Что сделать:** Дать пользователю возможность запускать сопоставимый бэктест обеих стратегий с историческими данными и настраиваемыми условиями исполнения, не меняя сохранённые профили.

**Зависимости:** профили из 02, реализованные торговые правила из 03 и доступная брокерская история для конкретного прогона (см. 01). Допуск нативных стопов и незавершённые сценарии восстановления робота не блокируют историческую симуляцию.

Status: done

- [x] Страница бэктеста позволяет выбрать стратегию; переход с дашборда и прямое открытие выбирают стратегию и последний сохранённый профиль дашборда.
- [x] Параметры стратегии можно изменять только для симуляции; при переключении стратегии сохраняются даты, комиссия и проскальзывание, а настройки пользователя и выбор на дашборде не меняются.
- [x] Форма включает начальные свободные деньги (по умолчанию 100 000 ₽), диапазон дат, комиссию (процент номинала), проскальзывание (неблагоприятное число шагов цены); нулевые издержки видны явно.
- [x] Бэктест использует брокерскую EMA, минутные свечи и общие с роботом правила сигналов, размера позиции, доборов, стопов, гэпов, разворотов и фильтра выходных. Публичный тест сравнивает вход, добор, разворот и гэп с `Robot` на одинаковых событиях и исполнениях. Торговые интервалы и доступное обеспечение оцениваются по модели симуляции, а не по данным торгового счёта.
- [x] Сигнал по закрытию исполняется на первом доступном минутном открытии в том же расчётном интервале; гэп — по открытию; внутрисвечный стоп — по уровню при касании или по открытию при перескоке уровня. Комиссия и проскальзывание применяются к каждому исполнению; разворот моделируется отдельными исполнениями выхода и входа.
- [x] История включительна по Москве; предшествующие свечи используются только для прогрева. Отсутствие требуемой EMA, прогрева или минутных свечей для целой свечи таймфрейма, а также расхождение OHLC приводят к отказу. Интервалы выводятся из свечей; пропуски минут внутри них отмечаются в отчёте без подстановки цен. ГО на лот равно числу пунктов цены фьючерса в рублях.
- [x] Отчёт показывает доходность в деньгах и процентах после комиссии, максимальную просадку, суммарную комиссию, график стоимости счёта, журнал исполнений, отдельные реализованный/нереализованный результаты и открытую позицию на конец периода без фиктивного закрытия.
- [x] Рядом с результатом показаны модель исполнения и её ограничения; результаты прогонов не сохраняются на сервере.

## Comments

- Реализован строгий режим для обеих стратегий с проверкой брокерских свечей, EMA, минутной истории, расписания и оценки ГО. Публичный тест сравнивает исполнения бэктеста и `Robot` на одинаковых событиях. Старые API-запросы без `kind` сохраняют прежнее поведение.
- Реальная приёмка прогона остаётся за задачей 01: в репозитории нет подтверждённого покрытия конкретного контракта и диапазона. Без него полный режим возвращает отказ. Схема `BACKTEST_COVERAGE_FILE` и команда для проверки без заявок описаны в `README.md`. Торговый допуск по стопам не изменён.
- Уточнение владельца после реализации: для симуляции выводить сессии из брокерских свечей, брать ГО равным числу пунктов цены в рублях на лот. Это заменяет требование файла и допускает минутные пропуски с явным предупреждением, если доступные минутные данные согласуются со свечой таймфрейма. Проверка биржевого календаря и фактического ГО не подменяется этой моделью; торговый допуск не изменён.
- 2026-11-24: действующая модель проверена в dev на брокерской истории IMOEXF за 22–23 ноября (1 час, EMA 55, ATR 20): 28 свечей периода, 55 свечей прогрева, 4 исполнения, итог −150 ₽, просадка 630 ₽, открытой позиции нет. Отчёт отметил 4 минуты без свечей. Заявки не отправлялись. Проверки бэкенда и все 30 браузерных тестов прошли.
