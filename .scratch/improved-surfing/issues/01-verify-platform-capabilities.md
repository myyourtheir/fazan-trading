# 01: Подтвердить техническую реализуемость

**Что сделать:** Подтвердить, какие необходимые возможности доступны для безопасной торговли новой стратегией и достоверного бэктеста, чтобы пользователь мог понять ограничения до включения функций.

**Блокируется:** Ничем (можно начать сразу).

Status: ready-for-agent

- [ ] Контролируемая проверка песочницы охватывает сохранение стопа при отключении, сверку после срабатывания и отсутствие двойного выхода при неатомарной замене уровня/объёма. Непрерывная защита при замене не требуется. Если проверка не устанавливает нужную гарантию, получено подтверждение контракта брокером или зафиксирован запрет торгового запуска.
- [x] Для конкретного прогона IMOEXF 22–23 ноября 2026 подтверждена достаточность брокерских свечей, минутной истории, EMA и прогрева по согласованной модели 04. Минутные пропуски указаны в отчёте; историческое расписание биржи и фактическое ГО не проверялись и больше не требуются для этой модели.
- [x] Результаты зафиксированы независимо: достаточность истории по модели 04 определяет доступность бэктеста для инструмента и диапазона, а подтверждение возможностей стопов — допуск торгового режима по 05. Симуляция не считается проверкой нативных стопов.
- [x] Ни один из этих результатов не блокирует разработку и автоматические тесты публичного поведения Robot с fake Broker и TradingStore; ограничения относятся к доступности соответствующих функций, а не к их реализации.

## Comments

### 2026-11-23 — предварительное исследование, допуск не подтверждён

**Стопы: торговый запуск «Улучшенного серфинга» запрещён до подтверждения
возможностей стопов и выполнения остальных условий допуска 05.** Задача 05
использует доказательства из 01, а не заменяет проверку или подтверждение
контракта брокером.
Контролируемые заявки не отправлялись, контракт брокера не получен: сохранение
стопа при отключении, сверка после срабатывания и безопасная замена уровня и
объёма без двойного выхода остаются непроверенными. Это не запрет разработки
или автоматических тестов `Robot` с fake `Broker` и `TradingStore`.

Доказательства возможностей, но не гарантий: установленный SDK
`@ttech-pub/grpc-node-client` 1.61.0 объявляет в
`compiled/sandbox.d.ts` методы `postSandboxStopOrder`,
`getSandboxStopOrders`, `cancelSandboxStopOrder`. В
`compiled/stoporders.d.ts` запрос выставления содержит клиентский `orderId`,
ответ содержит `orderRequestId` и `stopOrderId`, а записи списка содержат
`stopOrderId`, статус и опциональный `exchangeOrderId`, но не содержат
`orderRequestId`. Поэтому из типов не следует, что после потери ответа можно
однозначно найти исходный стоп по клиентскому ID; не следует и атомарность
замены или исход гонки отмены со срабатыванием. Наличие методов не является
доказательством корректного поведения песочницы. Официальные описания:
[выставление](https://developer.tbank.ru/invest/api/sandbox-service-post-sandbox-stop-order),
[список](https://developer.tbank.ru/invest/api/sandbox-service-get-sandbox-stop-orders).
Для снятия запрета нужны контролируемая проверка всех трёх сценариев и
проверка сверки по исходному ID; если эксперимент не устанавливает нужную
гарантию — подтверждение контракта брокером. Неопределённая отмена или
срабатывание не позволяют отправлять конкурирующий выход.

**История: покрытие конкретного инструмента и диапазона не подтверждено.**
Для первоначального исследования запросов к брокеру и архиву не выполнялось.
Следовательно, ни один конкретный
прогон новой стратегии нельзя объявить доступным на основании этого
исследования. Для каждого прогона независимо нужны подтверждённые минутные
свечи в торговых сессиях, брокерская EMA для всех необходимых свечей включая
прогрев, история свечей для прогрева ATR, историческое расписание данного
инструмента и диапазона и обоснованная оценка обеспечения, фиксированная на
прогон. При отсутствии любого компонента — объяснимый отказ без обрезания
диапазона и подмены данных; отсутствие сделок само по себе не доказывает
отсутствия данных.

Существующий `backend/src/infra/invest-sandbox.ts` вызывает `getCandles` и
`getTechAnalysis` для EMA; он не проверяет указанное полное покрытие.
`backend/src/core/backtest-history.ts` собирает свечи выбранного таймфрейма и
прогрев для существующего бэктеста, но не доказывает покрытие минутными
свечами, историческим расписанием, брокерской EMA и обеспечением новой
стратегии. Его текущую проверку нельзя считать подтверждением нового прогона.
Документация брокера описывает
[исторические котировки](https://developer.tbank.ru/invest/intro/intro/load_history)
и [ограничения свечей](https://developer.tbank.ru/invest/services/quotes/faq_marketdata);
глубина и полнота должны проверяться по фактическим инструменту и датам.
[Справочник MOEX ISS](https://iss.moex.com/iss/reference?lang=en) описывает
список исторических сессий только для фондового рынка; этого недостаточно как
подтверждения покрытия расписания фьючерса IMOEXF. Источник исторической оценки
обеспечения и её обоснование для конкретного прогона также не установлены.

Итоги независимы: неподтверждённые стопы не запрещают выпуск бэктеста при
подтверждённой истории; недостаточная история конкретного прогона не меняет
решение о допуске стопов. Критерии задачи остаются открытыми до конкретной
проверки и получения недостающих подтверждений.

### 2026-11-23 — конкретизация проверки истории

Проверочный кандидат — IMOEXF, 16–20 ноября 2026 включительно по Москве
(`[2026-11-15T21:00:00Z, 2026-11-20T21:00:00Z)`), 60 минут,
EMA 55 и ATR Уайлдера 20; выходные выключены. Кандидат для поиска прогрева —
9–15 ноября по Москве до начала диапазона, только для индикаторов, не сделок.
Нужно подтвердить достаточное число завершённых часовых свечей для EMA 55,
ATR 20 с предыдущим закрытием и начальной стороны пересечения, а также
наличие брокерской EMA на всех необходимых временных метках; выбранная неделя
не считается автоматически достаточной. При нехватке искать ранее и явно
зафиксировать фактическую границу, не сокращая сам диапазон прогона.

- **Идентификатор.** Поиск по репозиторию нашёл стандартный тикер
  `backend/src/core/strategy-settings.ts`, но не достоверный брокерский UID.
  `contract-a` и `contract-b` в `backend/src/core/sandbox.test-support.ts` —
  тестовые фикстуры, не UID инструмента. Его необходимо получить из каталога
  брокера и подтвердить соответствие инструменту на выбранных датах.
- **Минутные свечи и EMA.** Фактические запросы `getCandles` и
  `getTechAnalysis` не выполнялись: брокерский токен для исследования не
  предоставлен; в окружении нет переменной токена Invest, локальный `.env`
  содержит лишь ключ шифрования, а не токен. Доступность сохранённых
  пользователем учётных данных не предполагалась. Дополнительно проверка
  доступности `https://invest-public-api.tinkoff.ru/rest/` через `curl`
  завершилась ошибкой проверки TLS-сертификата (HTTP 000). Поэтому покрытие
  минутами на 16–20 ноября и брокерской EMA/часовыми свечами на всём прогреве
  и диапазоне неизвестно; отсутствующие интервалы данных отличить от закрытых
  сессий пока нельзя.
- **Историческое расписание.** Публичный запрос
  [MOEX ISS по IMOEXF](https://iss.moex.com/iss/engines/futures/markets/forts/securities/IMOEXF.json?iss.meta=off)
  вернул HTTP 200, `SECID=IMOEXF`, `BOARDID=RFUD` и `FRSTTRADE=2023-11-14`.
  Это карточка инструмента, не исторический календарь сессий и перерывов:
  расписание на прогрев и 16–20 ноября не подтверждено.
- **Обеспечение.** Та же текущая карточка содержит `INITIALMARGIN=2360.35`
  и `IMTIME=2026-11-21 10:00:07`. Это наблюдение не подтверждает историческое
  обеспечение на выбранную неделю и само по себе не обосновывает фиксированную
  оценку для прогона. Исторический источник и метод консервативной оценки
  ещё нужно установить.

Итого **ни один интервал выбранного прогона или прогрева пока не подтверждён
полным набором данных**; это неизвестное покрытие, а не доказательство
фактических дыр. Прогон следует отклонить с указанием неподтверждённых UID,
свечей/EMA и прогрева, расписания и оценки обеспечения, не сдвигая границы
и не подставляя локальную EMA или текущую маржу как историческую. Для
проверки нужны авторизованный доступ с корректной цепочкой TLS, сопоставление
UID, запросы минутных свечей по суточным окнам и EMA с проверкой каждой
необходимой свечи, подтверждённый архив сессий FORTS и обоснование оценки
обеспечения на период.

Политика независимых ограничений и запрета торгового запуска зафиксирована;
фактическое подтверждение истории и стопов остаётся открытым. Ни один из этих
нерешённых исходов не блокирует разработку или
автоматические тесты публичного поведения `Robot` с fake `Broker` и
`TradingStore`. Задача 05 потребляет доказательства стопов из 01 и проверяет
условия допуска собранного приложения; её выполнение само по себе не является
таким доказательством.

### 2026-11-24 — проверена история для согласованной модели бэктеста

В dev выполнен read-only прогон IMOEXF за 22–23 ноября 2026 включительно по Москве, 1 час, EMA 55, ATR 20. Брокерская EMA совпала по времени для всех 28 свечей периода и 55 свечей прогрева. Доступные минутные свечи согласуются с OHLC; внутри расчётных интервалов отмечены 4 минуты без свечей. Ранее рассмотренный диапазон 16–20 ноября этим прогоном не проверен. Архивное расписание и фактическое ГО не подтверждены: владелец заменил это требование моделью из 04. Проверка нативных стопов остаётся открытой, запуск заблокирован.

### 2026-11-25 — проверка нативных стопов в песочнице

- На выделенном пустом счёте выставили нативный рыночный стоп-лосс на один лот IMOEXF с уровнем значительно ниже текущей цены. Новый клиент видел активный стоп по брокерскому `stopOrderId`, но не по клиентскому `orderId`. После отмены список всех стопов показывал статус `CANCELED`.
- Для проверки восстановления после потери ответа повторили идентичный `PostSandboxStopOrder` с тем же клиентским `orderId` из другого клиента. API вернул **другой** `stopOrderId`; оба стопа одновременно были активны. Повтор запроса не идемпотентен и не подходит для восстановления по исходному ID. В рабочем роботе повторять такую заявку нельзя.
- Все тестовые стопы отменили, брокер подтвердил отсутствие позиций и активных заявок, включая стопы. Рыночные заявки не отправлялись; срабатывание стопа и гонку отмены со срабатыванием не проверяли.

Торговый запуск остаётся заблокирован. Для продолжения нужен способ однозначно сверить исходный стоп после неоднозначного ответа без повторного выставления, а затем — проверка срабатывания и безопасной замены.
