# ADR 0001: Слоистая структура бекенда

Status: accepted (2026-11-18)

## Контекст

Все 16 модулей бекенда лежали в плоском `backend/src/`: домен и сценарии, адаптеры gRPC-брокера и PostgreSQL, HTTP/WS-поверхность и композиция вперемешку. Человеку трудно найти нужный модуль, а граница «домен не зависит от инфраструктуры» держалась только на договорённости: единственное ребро core→infra (импорт типа `TokenCipher` в `sandbox.ts`) ничто не ловило, и новые могли появиться тихо. Порты при этом уже существовали (`Broker`, `TradingStore`, `MarketBroker`, `SandboxBroker`, `SandboxStore`, `StrategyStore`, `SessionStore`), инфраструктура их реализовывала — не хватало только видимой структуры и принуждения.

## Решение

Разнести `src/` по трём слоям и держать направление импортов жёсткой матрицей. Композиция остаётся в `main.ts`.

```
src/
  core/     домен и сценарии: crossing, robot, market-data, sandbox, strategy-settings, auth
  infra/    реализует порты core: invest-sandbox, postgres, db/schema, token-cipher
  api/      движущие адаптеры (HTTP/WS): app, *-routes, market-socket, request-validation, cookies
  main.ts   композиционный корень: env, конструирование, связывание
```

Матрица направлений импортов:

| Откуда \ Куда | core | infra | api |
|---|---|---|---|
| core | ✓ | ✗ | ✗ |
| infra | ✓ | ✓ | ✗ |
| api | ✓ | ✗ | ✓ |

`main.ts` и `test/` импортируют всё. Порты объявляются рядом с потребителем в core; инфраструктура удовлетворяет им структурно, без изменений на своей стороне. Файл, живущий в `src/` напрямую, допускается только один — `main.ts`.

Принуждение — механическое: `backend/scripts/check-layer-boundaries.mjs` проверяет матрицу в каждом `npm test`, без новых зависимостей. Правило также зафиксировано в `AGENTS.md` (раздел Trading code).

## Последствия

- Навигация: по имени папки понятно, где менять логику, где внешний сервис, где HTTP; новые модули кладутся в слой по смыслу.
- `core` можно читать и тестировать, не открывая ни SDK, ни Drizzle, ни express; все зависимости core приходят через его порты.
- Добавление инфраструктурной зависимости в домен (или прямой импорт из api в infra) ломает тест — нарушение заметно в первом же запуске, а не на ревью.
- Интерфейс `TokenCipher` объявлен в `core/sandbox.ts`; конкретный класс в `infra/token-cipher.ts` совместим с ним структурно — имя порта и имя реализации совпадают, это осознанно (как `PostgresTradingStore` реализует `TradingStore` без переименований).
- HTTP-статусы по-прежнему вшиты в `RobotError` и `SandboxError` (core «знает» транспортные коды). Это осознанное исключение из чистоты: коды зафиксированы контрактом и тестами; вынос маппинга в api — отдельная будущая задача.
- Относительные импорты с суффиксом `.js` (NodeNext) сохранены: дерево мелкое, алиасы путей не оправдывают дополнительную конфигурацию.
