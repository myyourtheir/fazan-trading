# Сёрфинг

Панель торгового робота для песочницы Т‑Инвестиций. Пока реализован локальный запуск и вход владельца; подключение брокера и торговля ещё недоступны.

## Запуск через Docker Compose

1. Скопируйте `.env.example` в `.env`. Задайте `OWNER_PASSWORD` (12–256 символов) и `POSTGRES_PASSWORD`; используйте разные пароли.
2. Выполните `docker compose up --build -d`.
3. Откройте `http://127.0.0.1:8080` и введите пароль владельца. Если задан `FRONTEND_PORT`, используйте его.

Миграции запускаются при старте бэкенда. PostgreSQL хранит данные в именованном томе; `docker compose down` останавливает приложение без удаления данных. Через внешний порт доступен только фронтенд, и только на loopback. Для HTTPS установите `COOKIE_SECURE=true`.

## Разработка без сборки Docker-образов

Требуются Node.js 24+ и доступный PostgreSQL. Для каждого приложения скопируйте его `.env.example` в `.env`. В `backend/.env` задайте адрес БД и пароль владельца; в `frontend/.env` при необходимости измените адрес бэкенда для прокси Vite.

- `backend/`: `npm ci`, затем `npm run dev`; проверки — `npm run typecheck`, `npm test`, `npm run build`.
- `frontend/`: `npm ci`, затем `npm run dev`; проверки — `npm run build`, `npx playwright install chromium`, `npm test`. Тест браузера использует подменный REST API, если адрес приложения не задан.

Для браузерной проверки реального Compose-развёртывания запустите из `frontend/` `npm test`, передав через окружение `SERFING_E2E_URL=http://127.0.0.1:8080` и `SERFING_E2E_PASSWORD` с паролем тестового владельца.

`node scripts/test-compose.mjs` из корня проверяет миграции на чистой PostgreSQL и сохранение сессии после пересоздания бэкенда. Скрипт создаёт и удаляет только своё временное Compose-окружение.
